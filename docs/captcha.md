# CAPTCHA Handling and Politeness Policy

> ⚠️ **Юридическое предупреждение.** Используйте ручное или внешнее решение капчи только для собственных ресурсов или при наличии письменного разрешения владельца сайта.

## Что считается капчей

Капча — это интерактивная проверка, предназначенная для защиты сайта от автоматизированных запросов. Клиент не пытается обходить защиту: при обнаружении известных виджетов (reCAPTCHA, hCaptcha и т. п.) запрос останавливается и требует человеческого участия.

## Политика вежливости клиента

HTTP-клиент обёрнут `PoliteHttpMessageHandler`, который:

- ограничивает частоту запросов на хост (`MaxRequestsPerSecondPerHost`, по умолчанию 0.35 rps);
- выполняет только один одновременный запрос на хост (`MaxConcurrencyPerHost` = 1);
- добавляет случайный джиттер 200–800 мс к каждому запросу;
- уважает `Retry-After` и повторяет запросы с экспоненциальной задержкой (коды 429/503/504, максимум 3 попытки);
- читает и кэширует `robots.txt` на 24 часа, учитывает `Disallow`, `Crawl-delay`, `Sitemap`;
- подставляет реальную браузерную `User-Agent` строку, а также заголовки `Accept-Language`, `Accept`, `DNT` без маскарада;
- применяет условное кеширование (`ETag`, `If-None-Match`, `If-Modified-Since`) для снижения нагрузки.

Все ограничения и заголовки настраиваются переменными окружения `POLITENESS_*` (см. `.env.example`).

## Обнаружение капчи

Детектор анализирует HTML-ответы и ищет признаки капчи (виджеты reCAPTCHA, hCaptcha, Cloudflare и т. п.). При совпадении клиент выбрасывает `ErrCaptchaRequiredException` с `CaptchaContext`, который содержит URL, тип, site key и HTML-превью.

Метрики:

- `captcha_detected_total` — количество обнаруженных капч;
- `manual_captcha_solved_total` — ручные решения капч;
- `blocked_by_robots_total` — блокировки по правилам `robots.txt`.

## Human-in-the-loop

В dev-режиме CLI включает `ConsoleCaptchaPrompt`, отображающий данные из `CaptchaContext` и запрашивающий ввод пользователя. Ввод токена приводит к повторной отправке запроса с решением. Диалог можно отменить, оставив строку пустой.

Интерфейс `ICaptchaPrompt` может быть реализован для других UI (например, dev-панели веб-приложения).

## Внешние провайдеры

Интерфейс `ICaptchaSolver` поддерживает три режима:

- `mock` — возвращает фиктивный токен, используется по умолчанию и в CI;
- `manual` — требует реализации `ICaptchaPrompt`;
- `external` — проксирует запросы через поддерживаемого провайдера (2Captcha/AntiCaptcha).

Использование внешнего провайдера разрешено только при выполнении **обоих** условий:

1. `ALLOW_EXTERNAL_CAPTCHA_SOLVER=true`;
2. домен цели присутствует в `ALLOWED_CAPTCHA_DOMAINS`.

Дополнительно нужно указать `CAPTCHA_PROVIDER=external` и `CAPTCHA_API_KEY`. Таймауты и интервал опроса регулируются `CAPTCHA_POLL_INTERVAL_SEC` и `CAPTCHA_TIMEOUT_SEC`.

## Переменные окружения

См. `.env.example` для безопасных значений по умолчанию. В CI используется `CAPTCHA_PROVIDER=mock`, внешние вызовы запрещены.

## Юридическое предупреждение

Обход защиты чужих сайтов запрещён. Разрешается работать только с собственными ресурсами или при наличии письменного согласия владельца. Любая интеграция с внешними провайдерами капчи должна быть одобрена юридически и технически.
